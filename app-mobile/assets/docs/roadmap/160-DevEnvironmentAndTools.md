## 知识点地图

- **知识类别**：开发环境与工具链——不属于任何一条技术路线，但每条路线的第 1 周都要面对：装什么、按什么顺序装、装完怎么验证、坏了怎么定位。
- **解决什么问题**：「配置环境两天，写代码十分钟」的入门劝退；「我这里能跑」的团队协作撕裂；换电脑时看着一堆配置不知道哪些要带走。
- **什么时候用到**：三个时机——第一次上手（照本篇顺序走一遍）；换电脑或重装系统（按依赖链重放并核对清单）；加入团队（用本篇的一致性实践对齐团队约定）。

环境问题有个恼人的特点：装的时候一切顺利就忘了它存在，出事的时候（毕业设计答辩前一晚）才发现自己完全不懂它为什么坏。本篇的目标不是列出所有工具，而是给你一套**顺序、验证与排查**的框架——工具会换，框架不变。

## 学习目标

读完本篇你将能够：

1. 说清「运行时 → IDE → Git → 数据库」安装顺序背后的依赖理由，而不是背清单；
2. 按场景选 IDE，而不是跟着论坛吵架站队；
3. 排查「装了但命令找不到」「版本不对」「我这里能跑他那里不能跑」三类高频环境事故；
4. 给自己或团队写一份环境搭建文档并验证可复现。

## 安装顺序及其依赖链

社区讲座里最常见的入门顺序是：装 JDK → 装 IDE → 装 Git → 装 MySQL。这个顺序不是随口排的，每一步都依赖前一步存在：

```text
1. 运行时/工具链（JDK、Python、Node、Go...）
   ↓ 理由：没有编译器与运行时，写什么都无法变成能跑的程序
2. IDE（IntelliJ IDEA、VS Code...）
   ↓ 理由：IDE 会在首次配置时扫描你装好的运行时（SDK 路径），
     顺序反了就要手动指路径，是新手第一大坑
3. Git
   ↓ 理由：独立于前两者，但 IDE 的版本管理面板需要 git 可执行文件在 PATH 里；
     越早装越早开始「每天一次 commit」的习惯
4. 数据库（MySQL、PostgreSQL、Redis...）
   ↓ 理由：第一阶段用不上，放在最后；但要在第 3 个月前装好，
     因为后端路线很快要连库
```

两个通用补充，无论什么路线都成立：

- **包管理器优先**：Windows 用 winget、macOS 用 Homebrew，能用包管理器装的别去官网下安装包——装、升级、卸载、查版本全部一条命令，换电脑迁移时这份命令清单本身就是环境文档；
- **每装一步立刻验证**：装完 JDK 敲 `java -version` 与 `javac -version`，装完 Git 敲 `git --version`。验证命令的输出（版本号）随手记进你的环境清单——三个月后排查问题，你很需要知道当时装的是什么版本。

## IDE 选型：先能用，再谈好用

选型口径一句话：**先用社区版/免费版把主线跑通，熟练后再考虑付费与高级工具**。具体到常见场景：

| 场景 | 首选 | 备选 | 一句理由 |
| --- | --- | --- | --- |
| Java 后端 | IntelliJ IDEA 社区版 | Eclipse | IDEA 对 Spring 的支持是行业默认体验，社区版已够学习期使用 |
| 前端 | VS Code | WebStorm | 免费、启动快、插件生态最大；WebStorm 的重构与框架集成更强，进阶后再换不迟 |
| Python/数据 | VS Code（装 Python 插件） | PyCharm 社区版 | 数据工作常在 notebook 里，VS Code 一站覆盖 |
| Go/系统 | VS Code 或 GoLand | - | 官方插件链完整 |

三条比选型更重要的纪律：

1. **一个方向一个 IDE**：同时开三个编辑器写同一个项目，配置、快捷键、格式化规则互相打架。学习期约束自己只用一个；
2. **读懂 IDE 的报错，而不是绕过它**：飘红先读红字。IDE 报「找不到符号」和编译器报的是同一件事，养成在 IDE 里读错的习惯，命令行排错就通了；
3. **别装"看起来有用"的插件**：插件越多，"打不开/卡死/行为怪"的概率越高。每个插件都要能回答"我哪个具体动作需要它"。

## 工具箱：装完顺手配好的六件

- **浏览器 DevTools**：F12 打开就是，前端路线第一天就要会用 Elements 与 Console 两个面板；后端也要会用 Network 面板看接口；
- **API 调试工具**（Postman 或同类）：接口还没写完就能按约定测；建集合（Collection）按项目归档请求，比翻聊天记录找 curl 命令体面得多；
- **数据库客户端**（Navicat/DBeaver/DataGrip 任一）：图形界面看表结构与数据，SQL 手练仍在命令行或模块环境做，两者不冲突；
- **终端**：Windows 用 Windows Terminal 加 Git Bash 或 PowerShell，macOS 用自带 Terminal 够用。先练熟 `cd`、`ls`、`历史命令` 三件事；
- **Git 图形界面**（可选）：IDE 内置的 Git 面板够用；命令行是必修，图形面板是效率件；
- **笔记与片段库**：环境命令、高频报错与解法、常用配置，落到一个随时能搜的地方。你的笔记在未来某次"环境又坏了"时，比任何教程都快。

## 装完即忘但出事才想：PATH、环境变量与版本管理器

**PATH 是什么**：命令行敲 `java` 时，系统按 PATH 里列的目录挨个找名为 java 的可执行文件。三类经典事故都在这里：

1. `命令找不到（command not found）`——安装目录没进 PATH，或者装完忘了重开终端（PATH 在终端启动时读取，改完不重开不生效）；
2. `版本不对`——PATH 里有两个同名命令（比如装过两个 JDK），排在前面的赢。排查命令：`where java`（Windows）或 `which -a java`（macOS/Linux），列出所有命中再对症删改；
3. `IDE 里能跑命令行不能跑`（或反过来）——IDE 与终端读到的 PATH 不同（图形界面启动的应用与终端的环境变量来源不同），把版本对齐到同一处即可。

**版本管理器**：同一台电脑要同时维护 Java 8 与 Java 17、Node 18 与 Node 22，靠手改 PATH 迟早出错。用版本管理器声明"这个目录用这个版本"：Java 用 SDKMAN、Node 用 nvm/fnm、Python 用 pyenv 或 uv。它们的共同模式是"装多个版本 + 按项目切换"，是团队协作的标配基建。

**为什么"我这里能跑"**：代码相同而行为不同，差异几乎总在环境——运行时版本、依赖锁文件是否提交、本地配置文件、数据库里的数据不同。解法不在道德呼吁而在工程手段：版本号文件提交进仓库（`.nvmrc`、`pom.xml` 的版本声明）、依赖锁文件（`package-lock.json`、`uv.lock`）永远提交、配置与代码分离（环境变量或本地配置文件不进仓库但提供模板）。

## 动手练习

练习一（新电脑从零到 Hello World，实机任务）。任务：假设这是一台全新电脑（没有就先建一个虚拟机或用学校机房机器），只看本篇的依赖链，完成"装运行时 → 装 IDE → 装 Git → 跑通 Hello World → 提交第一个 commit 到 GitHub"。要求每一步记录：用了什么命令、验证命令及其输出。完成后你手里就有一份个人环境文档的初稿。

练习二（诊断演习，故障注入）。任务：给你的环境故意制造一个故障——把 PATH 中运行时目录改名（或建一个假的同名命令挡在前面），然后在终端执行 `java -version`（或你主语言的对应命令），观察报错，用本篇的排查命令定位并修复。全程记录：现象、假设、验证命令、结论。这个四段式就是一切环境排错的通用模板。

<details>
<summary>参考排查记录（先自己写，再展开对照）</summary>

```text
现象：终端执行 java -version 提示 command not found，昨天还能用
假设：PATH 里 java 的目录失效，或 PATH 本身被改坏
验证：
  1. where java            → 无输出（说明 PATH 中无命中）
  2. echo %PATH%           → 看到 C:\jdk-17\bin 一项（目录应该存在）
  3. dir C:\jdk-17         → 系统找不到指定的文件（目录被删/改名了）
结论：JDK 目录被动过，PATH 指向空目录等于没装
修复：重装 JDK（或把 PATH 改回新目录），重开终端，java -version 恢复
```

对照要点：验证命令的顺序有讲究——先确认"命令在不在 PATH 里"（where/which），再确认"PATH 指的目录还在不在"，两级排查把"没装"与"装了但路径失效"区分开，这是新手最容易混的两种情况；最后一步"重开终端再验证"不能省，环境变量类修改不重开不生效，不重开就会误判为"修复无效"。

</details>

练习三（写一份团队环境文档）。任务：给你所在的学习小组或项目写一份《新人环境搭建指南》，内容五节：前置依赖链及顺序、每步安装命令（包管理器优先）、每步验证命令与预期输出、两个本项目特有的配置（数据库连接、环境变量模板）、两个本项目高频环境故障与解法。验收标准：交给一个没配过环境的同学，全程不看口述能跑通。

## 小结

环境搭建的本质是一条依赖链：运行时让代码变成程序，IDE 帮你写和调，Git 保住你的资产，数据库供数据——顺序由依赖决定，验证由命令完成。工具选型先免费后进阶、一方向一 IDE、插件按需装。PATH 与版本管理器是"出事才想起"的高危区，`where/which` 加"重开终端再验"是通用排查组合。"我这里能跑"的根治手段是工程化的：版本声明、锁文件、配置模板全部进仓库。
