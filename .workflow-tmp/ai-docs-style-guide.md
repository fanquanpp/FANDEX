# FANDEX AI 模块写作规范(全部写作 agent 必读)

## 最高约束

1. **全文禁止 emoji 与易渲染为 emoji 的符号**(U+2713 U+26A0 U+2605 U+2630 U+FE0F 等)。允许的符号仅:纯文本箭头 ← → ↓ × ≡ 与普通标点。
2. **简体中文**教学文档。代码注释用中文。
3. **文体 = 笔记教学文档,不是语法速查**。遮住文中所有代码块,剩下的文字必须能独立讲清这个主题的「为什么」与「是什么」;如果剩下的只是步骤标题,就是失败。
   - 主线:问题引入 → 心智模型(类比/原理/机制) → 极简操作(命令与代码嵌入解释中,不作为骨架) → 推导结论而非背结论 → 常见困惑 → 自检清单。
   - 范文(先读再写):`cnt-content/full/012-java/010-WhatIsJava.md`(问题引入、心智模型、对照表、动手实验的组织方式)。
4. **一份文件一个知识点**,不越界写别的主题;需要别的知识时用站内链接指过去。

## 硬性技术细节

- frontmatter **只写** title / description / difficulty / related / prerequisites。order/module/category/author/updated 由管线补全,不要写。
- description 必须用**单引号包裹**(防 YAML 冒号解析)。
- title 与各级标题:**CJK 与英文/数字之间留半角空格**(如「上下文窗口是稀缺资源」「GPT 与 Claude 的取舍」)。
- 代码块一律标注语言(python / typescript / bash / json / text / mermaid)。
- 每篇至少 1-2 张 mermaid 图(用 flowchart LR / sequenceDiagram 等基础布局,节点文字用双引号包裹)。
- 站内链接写根相对格式:`[文字](/模块id/NNN-文件名)`(不带 .md,不带 base 前缀)。
- frontmatter 的 related / prerequisites 只能引用**任务书里给出的真实存在文件名**,格式 `'模块id/NNN-文件名'`,每篇 2-5 条。不确定就不要写。
- 篇幅:正文 250-450 行(不含 frontmatter)。宁可深而透,不可凑行数。
- LaTeX 公式仅在确有必要时用($...$ 行内)。

## 事实纪律(2026-10 时点)

- 任务书里给出的协议版本、机制、生态事实以任务书为准;需要补充时可用 WebSearch/WebFetch 核实。
- **不要编造**具体价格、基准测试分数、排行榜名次;用区间与定性表述,易变事实标注「以官方文档为准」。
- API 示例以 OpenAI Python SDK 风格为基线(它已成为事实标准接口形状),提及 Anthropic SDK / OpenAI 兼容端点的对应关系。
- 提到具体模型时用泛称与系列名(如 GPT 系列、Claude 系列、Gemini 系列、GLM 系列、Llama、Qwen、DeepSeek),不锁定某个具体版本号作为「最新」,除非任务书明确给出。

## 禁止事项

- 禁 emoji(最高优先级)。
- 禁「基本写法:」式速查文体。
- 禁把整篇写成 SDK 文档翻译;SDK 细节点到为止,链接官方文档。
- 禁在正文里写「本文由 AI 生成」之类元话语。
- 禁使用 HTML 标签;纯 Markdown。
