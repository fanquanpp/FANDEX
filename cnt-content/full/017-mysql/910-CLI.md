## 连接：一条命令进交互界面

```bash
mysql -u root -p          # 回车后补输密码，凭据不留在命令行
mysql -h 127.0.0.1 -P 3307 -u app -p mydb   # 指定主机、端口、库名
mysql --default-character-set=utf8mb4 -u root -p   # 显式字符集，避免乱码
```

进入后提示符变成 `mysql>`，分号回车才执行。退出用 `exit` 或 `quit`。

### 凭据别写在命令行里

`-p密码`（不带空格）能跳过交互，但密码会出现在 shell history 和 `ps` 输出里。脚本的标准做法是配置文件：

```bash
# ~/.my.cnf，权限必须 600
[client]
user=monitor
password=你的密码
host=127.0.0.1

chmod 600 ~/.my.cnf
mysql -e "SELECT 1;"    # 自动读取凭据
```

多条凭据并存（开发一套、生产一套）用 `--defaults-extra-file=/path/file.cnf` 指定，同一原则：密码进文件不进行历史。

## 非交互执行：脚本和巡检的主力

```bash
# -e 直接执行，结果打stdout，退出码可用于脚本判断
mysql -e "SELECT COUNT(*) FROM charge_sessions;"

# 失败时退出码非 0，健康检查脚本的判据
mysql -e "SELECT 1;" && echo "DB OK"

# --batch 制表符分隔，配合 awk 提列
mysql --batch -e "SHOW STATUS LIKE 'Threads_connected';" | awk '{print $2}'

# 执行一个 SQL 文件（导入、迁移脚本）
mysql mydb < init.sql
mysql mydb -e "source /path/init.sql"    # 等价写法
```

## 交互界面里值得肌肉记忆的几件事

```sql
-- 1. 纵向显示：行宽爆掉时的救星（结果一列列竖着排）
SELECT * FROM charge_sessions\G

-- 2. pager：把查询结果直接交给 less / grep
pager less -S
SELECT * FROM information_schema.processlist;
nopager          -- 记得关掉

-- 3. tee：全程留档（事故排查时把整个会话录下来）
tee /tmp/session-20260928.log
notee
```

`\G`、`pager`、`tee` 是三个用过就回不去的效率开关。自定义提示符（显示当前连接的是哪个库哪个主机）：

```bash
mysql --prompt="[\u@\h:\d]> " -u root -p
```

## 常见困惑

- **"命令敲了没反应？"** —— 少了分号。`mysql>` 等你补 `;` 才执行，多行写一半也正常。
- **"中文变问号？"** —— 客户端字符集与库不一致，连接时加 `--default-character-set=utf8mb4`。
- **"CSV 导出？"** —— 交互内 `SELECT ... INTO OUTFILE` 需要服务器侧权限，更通用的做法是 `mysql --batch -e "..." > out.tsv` 在客户端侧落盘，列间是制表符。

## 教学自检（先遮住代码自己写，再对照）

遮码自检法：先只读题干，自己写/自己答，再展开参考答案对照。

1. 写出命令：脚本里连接数据库执行一条 SQL 并依据结果判断成败。凭据怎么传、成败看什么？

参考答案（先自己写，再对照）：

```bash
mysql -e "SELECT 1;" && echo "DB OK"    # 或 mysql --defaults-extra-file=/path/app.cnf mydb -e "..."
```

凭据走 `~/.my.cnf`（权限 600）或 `--defaults-extra-file`，绝不写 `-p密码`（会留在 shell history 与 ps 输出里）；成败看退出码——`-e` 的 SQL 失败时退出码非 0，这正是健康检查脚本的判据。

2. 概念自问：`\G`、`pager`、`tee` 三个交互命令各自解决什么问题？谁的效果是"会话级一次性"，谁会一直生效到你关掉？

参考答案（先自己答，再对照）：`\G` 让当前一条结果纵向显示（行宽爆掉时的急救），只影响该语句；`pager less -S` 把后续所有查询结果交给 less（横向滚动看宽表），持续生效直到 `nopager`；`tee /path/log` 把整个会话的输入输出持续留档（事故复盘要"我当时跑了什么"），直到 `notee`。一个是一次性的显示格式，两个是会话级开关——用完记得关，否则你奇怪"结果怎么被截断了/怎么在往文件里写"。

3. 判断题：`mysql mydb < init.sql` 与 `mysql -e "source /path/init.sql"` 完全等价，随便用。

参考答案（先自己答，再对照）：几乎等价（都是把 SQL 文件喂给服务器执行），但路径语义不同：`<` 重定向由 shell 打开文件——文件不存在时 shell 报错，脚本中止；`source` 由 mysql 客户端读取——路径错了报 client 错误且脚本可能继续往下跑。自动化脚本里前者更稳（失败即停），且注意 `source` 用的路径是 mysql 客户端所在机器的本地路径，不是服务器路径。

4. 概念自问：导出 CSV 给下游，为什么推荐 `mysql --batch -e "..." > out.tsv` 而不是 `SELECT ... INTO OUTFILE`？

参考答案（先自己答，再对照）：`INTO OUTFILE` 由**服务器进程**写文件——要求 secure_file_priv 授权目录与 FILE 权限，文件落在服务器磁盘，还要想办法搬回客户端；`--batch` 制表符分隔把结果写到客户端 stdout，重定向即落盘，零服务器配置。代价是 `\N` 表示 NULL、转义规则要跟下游约定。权限与运维成本更低的路径通常就是更对的路径。

## 自检清单

- 能不用 `-p密码` 明文完成一次脚本化连接；
- 会用 `-e`、`< file` 两个非交互入口，并解释退出码的用途；
- `\G`、`pager`、`tee` 各演练一遍。
