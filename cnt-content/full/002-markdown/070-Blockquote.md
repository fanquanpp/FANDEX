> **认知导入（Layer 1 进阶层）**
> 前置知识：060 列表语法（本篇 §2.4 会用到列表缩进规则）。
> 边界说明：引用（`>`）用于转述与摘录。列表语法已归并至 060 篇，本篇专注引用块本身及其与其他块级元素的组合。
> 强制练习：用 `>` 写一段引用，再在引用内嵌套一个列表；然后故意把缩进改错，观察层级如何塌掉。

## 1. 引用基础

### 1.1 基本写法

```markdown
> 这是一段引用内容
```

### 1.2 多行与多段

每行都以 `>` 开头即为连续引用；引用内用只含 `>` 的空行分隔段落：

```markdown
> 第一行引用
> 第二行引用
>
> 第二段引用（与上一段之间有空行）
```

### 1.3 懒延续：`>` 可以省略

引用的后续行即使不写 `>` 也会被并入引用（这叫懒延续，lazy continuation）：

```markdown
> 这行有引用符
这行没有，但仍属于引用
```

渲染后两行同属一个引用块。这个特性既是便利也是陷阱：引用结束后**必须留一个真正的空行**，否则紧跟着的普通段落会被"吸"进引用里。

## 2. 引用嵌套与其他元素

### 2.1 引用嵌套引用

`>>` 表示二层引用，`>>>` 三层，以此类推：

```markdown
> 外层引用
>> 内层引用
>>> 更深层引用
```

### 2.2 引用内含标题、列表与行内格式

引用块可以承载几乎所有块级元素，每行前加 `>` 即可：

```markdown
> ## 引用内标题
> - 列表项一
> - 列表项二
>
> **加粗** 与 *斜体* 均可
```

引用内的代码块同样可行，围栏式代码块每行都缩进在 `>` 之后：

````markdown
> 示例：
>
> ```bash
> npm install
> ```
````

### 2.3 引用打断段落

`>` 行可以紧跟在段落文字之后直接开始引用（无需空行）——这与"引用的懒延续会吞掉后续段落"是一体两面：段落后的 `>` 行成为引用的开头，而引用后的普通段落则可能被吸进引用。写完引用永远留一个空行，是最简单可靠的纪律。

### 2.4 列表项内放引用

`>` 缩进到列表项内容列即可：

```markdown
- 项目一
  > 项目一的说明引用
- 项目二
```

GitHub、Obsidian 的警报块/Callout（见 `markdown/180-AdmonitionCallout`）都是把提示内容装进引用块的产品化形态。

## 3. 常见陷阱

1. **引用后不留空行**：懒延续会把后面的普通段落吸进引用；引用结束后永远留一个空行。
2. **`>` 后空格数量不一致**：`> 文本` 与 `>文本` 多数渲染器宽容，但嵌套引用 `>>` 中间的空格会影响层级视觉，团队保持一种写法即可。
3. **引用嵌列表或列表嵌引用时缩进混乱**：引用内列表每行都要带 `>` 前缀；列表内引用缩进到内容列——两个方向都可以嵌，但缩进基准不同（前者对齐 `>` 后、后者对齐列表内容列），写之前先确认基准。

> 列表语法的完整规则（缩进层级、任务列表、列表内代码块与紧凑/松散列表）已归并至 `markdown/060-ListSyntax`，本篇专注引用块。

## 小结

- 初学者要点：引用每行加 `>`，嵌套引用用 `>>`；引用结束后留空行，防止后续段落被懒延续"吸进去"。
- 进阶注意：懒延续让 `>` 可以省略但也制造粘连；`>` 行可紧跟段落直接开始引用；引用内可承载标题/列表/代码块等几乎所有块级元素；警报块（180 篇）是引用的产品化形态。
