## 学习目标

写代码的第一道坎往往不是语言，而是操作系统的基本操作。读完本篇，你应该能：

1. 准确说出文件、文件夹、路径、扩展名的含义，并在自己电脑上指出它们的例子；
2. 区分"隐藏扩展名"造成的常见坑；
3. 独立完成一次规范的软件安装与验证；
4. 理解"以管理员身份运行"和"环境变量"这两个高频报错的根源。

## 前置知识

已阅读 [编程零基础第一课](/start/010-ProgrammingStartGuide)。本篇不写任何代码，全部操作都在图形界面完成。

## 文件与文件夹：一切的起点

计算机里所有信息都以**文件（file）**形式存储。一张照片是一个文件，一首歌是一个文件，你以后写的每一行代码也是一个文件。**文件夹（folder，也叫目录 directory）**用来组织文件。

自己动手验证：

1. 打开"文件资源管理器"（Windows 快捷键 `Win+E`）或"访达"（macOS 快捷键 `Cmd+N`）；
2. 进入"文档"，新建一个文件夹，命名为 `my-code`——**这将是本教程所有练习代码的家**；
3. 在里面再建一个 `week1` 子文件夹。

```text
文档/
  my-code/            <- 你的代码根目录
    week1/            <- 第一周练习
```

这个动作看似平淡，但它建立了本教程最重要的习惯：**项目即文件夹**。以后每个练习、每个项目都是一个独立文件夹，文件不乱放，工具才能正确工作。

## 路径：文件的"家庭住址"

**路径（path）**是描述文件位置的字符串。两种写法：

- **绝对路径**：从磁盘根开始的完整地址，如 Windows 的 `C:\Users\你的用户名\Documents\my-code\week1`，macOS 的 `/Users/你的用户名/Documents/my-code/week1`；
- **相对路径**：以"当前所在位置"为起点的地址，如你在 `my-code` 里时，week1 的相对路径就是 `week1`。

两个特殊符号贯穿整个编程生涯：

| 符号 | 含义 | 例子 |
| --- | --- | --- |
| `.` | 当前目录 | `./app.js` 指"当前文件夹里的 app.js" |
| `..` | 上一级目录 | `../week1` 指"上一级文件夹里的 week1" |

动手环节：在 `week1` 里新建一个文本文件 `notes.txt`，然后用文件管理器的"属性"（Windows 右键）或"显示简介"（macOS 右键）查看它的完整路径，抄在纸上。以后每个报错里出现的路径，你都能立刻读懂它在指哪个文件。

**注意斜杠方向**：Windows 用反斜杠 `\`，macOS 和 Linux 用正斜杠 `/`。网页地址永远用 `/`。这也是同一份代码在不同系统上路径报错的高发原因，记住这个差异，以后遇到能省半小时。

## 扩展名：文件类型的标签

文件名最后一个点后面的部分叫**扩展名（extension）**，用来标记文件类型：`photo.jpg` 是图片，`song.mp3` 是音频，`app.js` 是 JavaScript 代码文件。

第一课的坑在这里：**Windows 默认隐藏已知扩展名**。你看到的 `notes.txt` 实际可能是 `notes.txt.txt`。开发者必须先打开扩展名显示：

- Windows 11：文件资源管理器顶部"查看"菜单 → "显示" → 勾选"文件扩展名"；
- macOS：访达菜单"设置" → "高级" → 勾选"显示所有文件扩展名"。

以后你还会遇到这些常见扩展名，现在混个眼熟，它们会在后续模块中逐一登场：

| 扩展名 | 类型 | 对应本仓库模块 |
| --- | --- | --- |
| `.js` / `.mjs` | JavaScript 代码 | javascript |
| `.ts` | TypeScript 代码 | typescript |
| `.py` | Python 脚本 | python |
| `.html` / `.css` | 网页结构与样式 | html5 / css |
| `.json` | 配置与数据格式 | 各模块工程化章节 |
| `.md` | Markdown 文档（本仓库本身） | markdown |
| `.exe` / `.dmg` / `.deb` | 三大系统的安装包 | 本篇下一节 |

## 安装软件：开发者的方式

零基础阶段你需要的软件都在 [开发环境搭建](/start/030-DevEnvironmentSetup) 一篇里逐个带装。这里先讲清原理，让安装不再"碰运气"。

**图形安装包**：Windows 下载 `.exe` 或 `.msi` 双击安装；macOS 下载 `.dmg` 打开后把图标拖进"应用程序"。要点只有一个：**从官网下载，不要从搜索引擎推荐的下载站下载**（捆绑软件重灾区）。本仓库所有教程给出的都是官方地址。

**包管理器（进阶预告）**：开发者的主流方式是用命令行安装软件——Windows 有 `winget`，macOS 有 `brew`。好处是可脚本化、版本可控。零基础阶段先会双击安装，包管理器会在 [终端与命令行入门](/start/040-TerminalAndShellBasics) 之后的实践中自然引入。

**安装后验证**：装完不等于装好。验证的标准做法是打开终端输入软件的命令加版本参数，例如装完 Node.js 后运行 `node --version`，能看到版本号（如 `v22.x.x`）才算成功。这个"安装即验证"的动作以后会重复上百次，现在就养成习惯。

## 管理员权限：很多报错的真正原因

系统核心目录（如 `C:\Program Files`）受保护，写入需要**管理员权限**。典型症状：安装或运行时提示 `permission denied`、`EACCES`、`访问被拒绝`。

处理原则：

1. **优先绕开，而不是硬闯**：把项目放在用户目录（如 `C:\Users\你\my-code`），不要放在 `C:\Program Files` 或桌面以外的系统目录，日常开发就极少需要管理员权限；
2. 确实需要时（如全局安装某些工具），Windows 用"以管理员身份运行"打开终端再执行命令；macOS 在命令前加 `sudo` 并输入开机密码；
3. **不理解的高权限操作一律拒绝**——这是安全底线，与本仓库 [网络安全](/cybersecurity/010-SecurityBasicsDefense) 模块的理念一致。

## 压缩包、剪贴板与快捷键：效率的隐形基础

三个不起眼但每天都在用的技能：

- **压缩与解压**：`.zip` 双击即可解压（Windows 11 与 macOS 原生支持）。以后下载的项目源码、工具包多是压缩包，解压到非中文、无空格的路径可避免大量诡异报错（如 `C:\code\my-app` 优于 `C:\Users\你 的 文件夹\新建文件夹 (2)`）；
- **剪贴板历史**：Windows 开启 `Win+V` 剪贴板历史，macOS 记住 `Cmd+C/V` 之外还有 `Cmd+Shift+V`（粘贴纯文本，从网页复制代码时避免带入格式）；
- **窗口与切换**：`Alt+Tab`（Windows）/ `Cmd+Tab`（macOS）切换窗口；`Win+左右方向键` 让两个窗口各占半屏——以后"左边看教程、右边写代码"是标准学习姿势。

## 浏览器不只是用来刷网页

从今天起，把 Chrome 或 Edge 当成开发工具。按下 `F12`（macOS 下 `Cmd+Option+I`）打开**开发者工具（DevTools）**，你会看到一个陌生但强大的面板。

本阶段只需要认识两处：

- **Console（控制台）标签**：可以直接输入 JavaScript 并立即执行——[第一门语言体验](/start/060-FirstProgramJavaScript) 的主战场；
- **Elements（元素）标签**：实时查看网页的 HTML 结构——以后学 HTML 时的解剖台。

顺手做两件事：把浏览器更新到最新版；把默认搜索引擎换成支持英文检索的（检索英文技术问题的结果质量显著高于中文）。

## 常见困惑

**"C 盘、D 盘是什么？macOS 怎么没有？"**——Windows 把存储分成多个盘符（C、D...），macOS 和 Linux 只有一棵从根 `/` 出发的目录树。初学建议：代码统一放用户目录下（跨平台习惯一致，权限问题最少）。

**"64 位、32 位是什么？下载哪个？"**——指 CPU 一次能处理的数据宽度和对应的操作系统。2026 年在售的电脑全是 64 位，下载软件选 `x64` / `ARM64`（苹果 M 系列芯片与部分骁龙笔记本）即可。搞不清就选官网默认推荐项。

**"为什么教程里的按钮和我的不一样？"**——操作系统版本、软件版本差异会导致界面细节不同。学会按"功能名"搜索（如"Windows 11 显示文件扩展名"），而不是按"我看到的按钮样子"描述问题。
