## 技术世界地图：三段式直觉

在下决定之前，先把整个技术世界压缩成一张可以一句话复述的地图。行业讲稿里流传最广的版本把技术栈分三段：**前端技术**（HTML/CSS/JavaScript，进阶 Vue3 或 React）、**后端技术**（Java/Spring Boot 与 MySQL/Redis 为典型组合）、**工程化技术**（Git/GitHub、Docker、Linux）。配合两个餐厅类比，方向选择就有了直觉：

- **前端 = 餐厅服务员**：顾客看到和交互的一切——菜单好不好翻、菜上得快不快、结账顺不顺。特点是所见即所得，改一行代码刷新就能看到效果，适合喜欢视觉反馈的人；类比里服务员直接面对顾客，前端直接面对用户；
- **后端 = 后厨加仓库**：点单之后发生的一切——下单、扣库存、出餐、记账，用户看不见但停摆就出大事。登录、支付、存数据、给前端提供 API 都在这里。特点是生命周期长、逻辑密度高，适合喜欢逻辑推理的人；
- **工程化 = 餐厅的运营制度**：让前两段能协作、能复制、能扩张的部分——版本控制（谁改了什么）、容器化（换个厨房菜味道不变）、CI/CD（新菜自动上架）。讲稿里那句定性值得记住：**工程化是区分业余和专业的关键**。

选语言时常问"后端选哪个"，一张对比表给结论：

| 语言 | 特点 | 典型去向 |
| --- | --- | --- |
| Java | 稳定、生态完善 | 企业级系统、大厂与国企外包生态 |
| Python | 简洁、AI 生态友好 | 数据分析、AI 应用、脚本自动化 |
| Go | 高性能、并发原生 | 云原生、微服务、基础设施 |
| Node.js | 前端友好、全栈同语言 | 全栈小团队、实时应用 |

表背后的选择观比表本身重要：**语言只是工具，核心是编程思维；学好一门，其他容易迁移**。第一门语言值得按"目标岗位用什么"来选，而不是按"哪个语言最好"来吵。

数据库的选型阶梯同样一句话：**先学 MySQL 掌握 SQL 基础，再学 Redis 理解缓存**。MySQL 是关系型数据库里最流行、资料最全的入门首选；PostgreSQL 功能同样强大且开源免费，学到中后期再对比不迟；Redis 这类非关系型数据库解决的是缓存与高速读写场景，和 MySQL 是互补不是替代——这也是"数据库路线"（[数据库方向](/roadmap/100-DatabaseRoute)）的默认顺序。

## 如何选路线：三问决策法

**第一问：你想做出什么？**（兴趣与成果物驱动）

- 想做看得见的界面 → 前端、移动端；
- 想做看不见但撑起一切的服务 → Java/Go/Node 后端；
- 想跟数据与模型打交道 → Python 与 AI；
- 想做能玩的东西 → 游戏开发；
- 想让系统跑得稳、上得快 → 云与运维；
- 不确定 → 前端（成果反馈最快，初级岗位供给最多，试错成本最低）。

**第二问：市场要什么？**（生存现实）

零基础转行者优先看岗位绝对数量：前端与 Java 后端是中国市场岗位量最大的两块；Node 全栈适合小公司与远程工作；测试是转行门槛相对最低的入口。注意"市场大"与"竞争激烈"同时成立——最终拼的还是执行质量。

**第三问：你每天能投入多少？**

- 每天 2 小时以上：按路线完整节奏走；
- 每天 1 小时左右：用路线中标注的"最小闭环"子集，周期放长 50%；
- 每周不足 5 小时：先只做阶段 1，站稳再谈方向。

三问之后**写下你的选择与理由**，贴在显眼处。6 个月内不换路线（换语言不算换路线，比如前端内部的 React 换 Vue）。

## 路线文档的统一读法

每条路线文档都按同一骨架组织，标准用法如下：

```text
1. 岗位画像     确认"这是我想要的工作"，对齐预期
2. 技能树       全局一眼：哪些必学、哪些加分
3. 三阶段计划   第 1-3 月 / 4-6 月 / 7-12 月，每阶段绑定具体文档与项目
4. 检验项目     每阶段的验收项目与验收标准，做不出来就不进下一阶段
5. 常见弯路     别人踩过的坑，逐条自查
6. 求职准备     作品集、简历、面试的最后一公里
```

执行原则：

1. **文档链接必须真的点开学**：路线图只给顺序和验收，知识本体在各模块文档里；
2. **检验项目是铁门槛**：项目做不出来，说明上一阶段有欠账，回退补齐，而不是硬闯；
3. **进度可视化**：把路线复制成自己的清单（纸、表格或本库进度系统都行），完成一项勾一项；
4. **AI 工具全程按 [AI 协作开发指南](/roadmap/150-AICollabWorkflow) 的纪律使用**，并回到 [方法论](/start/050-LearnHowToLearnProgramming) 的教练四角色：让 AI 出题点评，不让 AI 代写项目。

## 动手验证：把选择变成今天的三个动作

决策框架读完不等于决策做完。路线选择最大的风险不是选错，而是「选了但没启动」——热情耗在反复比较上，第一行代码始终没写。下面三个动作按时间盒设计，今天就能全部完成，总耗时不超过两小时：

1. **30 分钟：写决策备忘录。** 不开电脑也行。拿一张纸回答三个问题：我的第一问答案（想做出什么）、我的第二问答案（市场依据，写出至少一条具体的招聘平台检索结果而不是感觉）、我每周可投入的真实小时数（按最近四周的平均值算，不按理想状态算）。写完拍照存档——六个月后动摇时，这份备忘录比任何鸡汤都有用。
2. **60 分钟：跑通目标语言的最小程序。** 从选定路线的技术栈里挑主线语言（前端选 JavaScript，Java 路线选 Java，Go 路线选 Go），完成安装加 Hello World 加一次报错修复。故意把代码改错一次、读懂报错、再改回来——这一来一回比顺利跑通更重要，它验证的是你的报错阅读能力，而不是复制粘贴能力。
3. **30 分钟：建仓库、写第一篇进度日志。** 在 GitHub 建一个学习仓库，README 写上路线选择与 12 个月的目标产物，再建一个 `log/2026-10.md` 写第一篇周记（本周做了什么、卡在哪、下周做什么）。仓库与周记是整条路线的进度凭证，从第一天就开始攒。

三个动作完成的标准不是「感觉不错」，而是可检查的产物：一份备忘录照片、一个能运行的程序、一个带首篇周记的仓库。产物缺一个，说明某个动作还没真做。

## 路线进度的度量：三个仪表

「计划跟不上了怎么办」这类问题之所以难回答，是因为多数人只有一种进度感知方式——「我感觉自己学了不少」。感觉会骗人，仪表不会。给整条路线装三个仪表，每周日晚花 15 分钟读一次数：

**仪表一：检验项目完成度（主仪表）。** 数一数当前阶段要求的检验项目，完成了几个、各自的验收标准达成了几条。这条仪表每周只动一点是正常的——检验项目本来就是周级别的工程。它连续四周不动，就是明确的报警：要么方法出了问题，要么投入出了问题，需要回头查，而不是继续「学」。

**仪表二：可复述知识数（学习质量）。** 每周从当周学过的内容里挑三个概念，不看资料向一个假想的听众各讲五分钟（自言自语或写小作文都行）。讲得顺的算「已掌握」，卡壳的记进「欠账本」。这个仪表防的是「收藏式学习」——看了很多、存了很多，能复述的没有几个。

**仪表三：连续学习天数（习惯强度）。** 不要求每天学两小时，只要求每天碰一次主线（15 分钟读一节文档也算）。这条仪表的唯一目标是不断签。学习行为研究的共识是：习惯强度主要取决于频率而非单次时长，三天不碰，重启成本会翻倍。周记里记一个连续天数即可。

三个仪表的读法也定好：仪表一是方向（做没做对事），仪表二是深度（做的事有没有沉淀），仪表三是惯性（能不能持续做）。方向对但深度不足，放慢速度补练习；深度够但惯性断了，缩小每日任务先续上惯性。对着仪表做调整，比对着焦虑做调整可靠得多。

## 常见困惑

**"能不能同时走两条路线？"**——阶段 1 完全可以（公共底座重合度高），阶段 2 起主线唯一。用"主线 80% 时间 + 支线 20% 时间"的配比，支线仅限每日一题式的轻量推进。

**"路线计划跟不上了要放弃吗？"**——计划是用来对齐方向的，不是用来产生负罪感的。落后时做减法：砍支线、砍加分项，保主线必学项。判断标准始终是检验项目而非计划表。

**"AI 都能写代码了，现在学这些还有意义吗？"**——正因为 AI 能写，**判断 AI 写得对不对、安全不安全、性能好不好**的能力成了新的门槛，而这个能力只能来自基础训练。路线里的项目都要求"自己先写、AI 后评"，就是针对这个新常态设计的。
