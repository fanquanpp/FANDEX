## 前置知识

- 已完成 [C 零基础起步](/c/010-CZeroBasisStart)：gcc 可用，编译与运行两步走熟练。

## 学习目标

读完本文你将能够：

1. 用「信任程序员、小标准库、零运行时开销」三个关键词概括 C 的设计哲学；
2. 说出 C 标准演进的主线（C89 → C99 → C11 → C17 → C23），知道去哪里查当前编译器的支持度；
3. 描述从源码到可执行文件的四个阶段（预处理、编译、汇编、链接）；
4. 对照 Java/Python/JS，说出 C 在「谁替你做事」上的根本差异。

预计 30 到 45 分钟。

## 1. 你现在要解决什么问题

上一篇你已经「会用了」。在使用之前，值得花 30 分钟回答「它为什么长这样」——C 的每个「麻烦」（手动管理内存、没有现成的哈希表、字符串要自己数长度）都不是设计失误，而是**设计哲学的直接推论**。理解哲学，后面的每个坑你都能预判；不理解，每个坑都像故意刁难。

## 2. 先试试看：让编译器交出四个阶段

上一篇「编译两步走」其实是一条流水线的缩写。用 gcc 的分阶段开关把流水线拆开看：

```bash
gcc -E hello.c -o hello.i    # 阶段一：预处理（展开 #include，文件膨胀到上千行）
gcc -S hello.c -o hello.s    # 阶段二：编译成汇编（能读到 mov、call 这些助记符）
gcc -c hello.c -o hello.o    # 阶段三：汇编成机器码（二进制，打开是乱码是正常的）
gcc hello.o -o hello         # 阶段四：链接（把库里的 printf 接进来，产出可执行文件）
./hello                      # Hello, C!
```

打开 `hello.i` 搜 `printf`——你会看到 stdio.h 的全部内容被原样展开进来。**`#include` 就是「把文件内容复制到这里」**，这个认知会让你立刻明白头文件重复包含为什么会报错。

## 3. 核心概念：三个哲学关键词

**信任程序员**：C 不检查数组越界、不阻止你把指针指向任意地址。它假设你知道自己在做什么——这份信任换来了极限性能与极限自由，代价是错误要靠纪律与工具（ASan、Valgrind）自己兜底。本仓库 210 篇的事故实录里你会反复见到这份「信任的账单」。

**小标准库**：C 标准库只有几十个头文件（字符串、文件、数学、内存），没有哈希表、没有正则、没有 HTTP 客户端。需要什么，要么自己造（练功的好机会，毕业项目就这么设计），要么引第三方库。对照 Python「电池全含」的哲学，C 是「给你刀与火，自己做饭」。

**零运行时开销**：C 没有 VM、没有垃圾回收器、没有解释器垫在中间。程序就是机器指令本身——这是操作系统内核、汽车固件选择 C 的根本原因：**每一字节的内存、每一纳秒的 CPU 都可预算**。

## 4. 标准演进主线（一张表，细节链 C23 专篇）

| 标准 | 年份 | 你最有感的部分 |
| --- | --- | --- |
| C89/C90 | 1989 | 第一个 ISO 标准，经典的 K&R 风格在此定型 |
| C99 | 1999 | 行注释 `//`、`for` 内声明变量、`stdint.h` 固定宽度整型 |
| C11 | 2011 | 多线程 `<threads.h>`、边界检查接口、泛型宏 |
| C17 | 2017 | 仅缺陷修订，无新特性 |
| C23 | 2023 | `nullptr`、`auto`、数字分隔符、`bool` 成关键字（[专篇详解](/c/520-C23CoreFeatures)） |

编译器对标准的支持度随版本不同，写代码前用 `gcc -std=c23` 这类开关显式声明目标标准；支持矩阵的查法在 C23 深水区篇有完整演示（验证于 2026-09，以 [cppreference C 页](https://en.cppreference.com/w/c) 为准）。

## 5. 对照表：C 在语言地图上的位置

| 你关心的事 | Python | Java | JavaScript | C |
| --- | --- | --- | --- | --- |
| 谁翻译你的代码 | 解释器逐行 | 编译为字节码跑在 JVM | 引擎即时编译 | 编译器直出机器码 |
| 内存谁管 | 垃圾回收 | 垃圾回收 | 垃圾回收 | 你自己 |
| 标准库 | 巨大 | 大 | 中 | 极小 |
| 典型战场 | 脚本/数据/AI | 企业后端/Android | 网页/全栈 | 内核/嵌入式/一切的地基 |

没有「最好」只有「合适」；C 的不可替代性在于最下面那行——**所有其他语言的运行时，最终都是 C 的作品或邻居**。

## 6. 修改实验

1. 把 `#include <stdio.h>` 注释掉再编译，读第一条报错（`implicit declaration of function 'printf'`）——理解头文件与声明的关系；
2. 在 hello.c 里故意写 `#include <stdio.h`（少个尖括号），读预处理阶段的报错，确认它发生在编译报错之前；
3. 用 `gcc -E` 分别编译「含 stdio.h」与「空文件」两个版本，对比 `.i` 文件行数，量化一次 `#include` 的代价。

## 7. 小练习

预测题：`gcc -S` 产出的 `.s` 文件里能看到变量名 `score` 吗？为什么？（提示：汇编层面还有什么「名字」。）

修改题：把上一篇的 hello.c 改成输出三行 ASCII 小旗（`*`、`**`、`***`），分阶段编译一遍完整流水线，确认四步产物都在。

修 Bug 题：同事说「我加了 `#include <stdio.h>`，但 gcc 说 printf 隐式声明」。他的编译命令是 `gcc -std=c17 hello.c`，gcc 版本 13——给出最可能的两个原因与排查命令。

挑战题（不看提示）：用四个阶段各自的 gcc 开关，把「hello.c → 可执行文件」完整手工走一遍，每步记录产物大小（`ls -l`），回答：链接前后产物大小为什么骤变？把答案写成三行注释放进源码。

## 8. 什么时候应该 / 不应该选 C

应该：目标含嵌入式、内核、驱动、性能工程，或「想看穿其他语言的运行时」。

不应该：需要快速交付业务功能（Web 与脚本请用更上层的语言——本仓库 python/javascript 主线都在等你）；团队里没人愿意为「信任程序员」支付纪律成本时慎选。

## 本章总结

C 的小、快、信任程序员是一枚硬币的三面：标准库小所以运行时轻，零运行时开销所以快，信任程序员所以自由与危险并存。四阶段流水线（预处理→编译→汇编→链接）解释了编译报错与链接报错的分界。带着哲学视角写 C，坑会变成课程。
