## 1. 五类文体占比（按抽样估计）

| 类别 | 占比 | 判定标准 |
| --- | --- | --- |
| A 问题驱动实践型 | 约 24%（14 篇） | 场景/问题引入、可运行代码、动手环节、错误分析 |
| B 结构化教学型 | 约 19%（11 篇） | 讲解 + 代码 + 小结，但零练习零动手 |
| C 概念堆砌型 | 约 24%（14 篇） | 定义/表格/命令罗列为主，代码少或孤立 |
| D 学术膨胀型 | 约 27%（16 篇） | 形式化定义、理论推导、历史演化等学究式展开，篇幅远超教学需要 |

结论：约 70%（C+D+E）的抽样文档没有「读者要做点什么」的环节；把无练习的 B 类计入则约 90%。A 类高度集中在 001-start 与 09-18 人工重写批。

## 4. 与理想教学闭环的结构对照

批量生成模板骨架：前置知识 → 学习目标（伪目标：复读章节标题）→ 历史动机与演化 → 形式化定义 → 理论推导与证明 → 代码示例 → 对比分析 → 常见陷阱与反模式 → 工程实践 → 案例研究 → 附录速查表。

与理想闭环「问题 → 示例 → 运行 → 修改 → 练习 → 调试 → 应用」逐环对照，缺口是系统性的：

1. 「问题」被排到最后（案例研究在第 8 章），开头是历史与形式化，动机倒置；
2. 「运行」缺失：代码是展示性片段，极少给预期输出，从不要求读者执行并核对；
3. 「修改」缺失：没有「把这段改成 X 会怎样」的变体任务；
4. 「练习」缺失：模板本身没有练习栏位（algorithm 模板有但未填充）；
5. 「调试」被降格为散文式「常见陷阱」罗列，不与真实报错文本关联；
6. 「应用」被替换为清单式「工程实践/最佳实践」叙述，读者没有产出物。

09-18 人工重写批恰好逐环补齐了这些缺口，证明文体问题已被本项目自己解决过一次，缺的是把该文体推广为全库标准。

## 6. 结论

1. 库主的判断成立：这不是「文笔问题」，而是「文体问题」——约 1663 篇批量文档的模板本身就没有为「学」而设计。
2. 质量与批次强相关：人工重写批已证明正确文体在现有管线下完全可行。
3. 最紧迫的不是平均提高质量，而是按优先级处置：零基础主线（start → python/javascript/html5/css/git）上的 D 类文档优先重写，深水区参考书式大文件降级为「参考资料」定位或拆分。
