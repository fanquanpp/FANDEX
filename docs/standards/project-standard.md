# 项目标准（project-standard）

## 1. 项目分层（Level 0-7）

每个学习路径的阶段之间必须有项目锚点，规模逐级上升：

| Level | 形态 | 参考规模 |
| --- | --- | --- |
| 0 | 极小实验（REPL 里验证一个行为） | 5 分钟 |
| 1 | 单知识点小程序 | 20 分钟 |
| 2 | 多知识点组合（变量+循环+条件） | 1 小时 |
| 3 | 模块化脚本（函数拆分） | 半天 |
| 4 | 数据持久化项目（文件/SQLite） | 一天 |
| 5 | API/网络项目 | 一天 |
| 6 | 完整小型应用（含测试） | 两天 |
| 7 | 综合毕业项目（需求→部署全流程） | 一周 |

## 2. 项目篇结构（借鉴 freeCodeCamp 的 user stories 验收）

1. **背景与目标**：做出什么、给谁用、学完本项目你能新增什么能力；
2. **编号 user stories**：每条都是可检查断言（「运行 `python ledger.py`，输入一条账目后按 q，终端打印合计」），分「必做」与「Extra credit（选做）」两组；
3. **里程碑拆解**：按功能切成 3-6 个可独立验证的步骤，每步给「完成后应该看到什么」；
4. **提示区**：只给数据结构建议、相关文档链接、常见坑；不给完整代码；
5. **验收清单**：user stories 逐条 checkbox + 自测命令；
6. **参考实现**：不给正文；确需展示时放「完成后再看」的折叠段或指向独立示例仓库。

## 3. 反抄袭与防照抄

- 项目正文不提供完整答案代码；示例代码只出现在「讲解概念」的上下文且与项目要求不同构；
- 鼓励变形与个性化：每个项目必须包含至少一处「自己决定」的自由度（命名、数据、功能取舍）。

## 4. 真实感要求

- 项目使用真实数据源或作者真实项目（见 code-example-standard.md 第 2 节的仓库清单）；
- 毕业项目（Level 7）必须走完整工程链：需求分析 → 技术选型 → 初始化 → Git 仓库 → 目录设计 → 实现 → 测试 → README → 部署（静态托管或免费层云服务）；
- 完成标志是「作品可访问、仓库可复现」，不是「代码写完了」。
