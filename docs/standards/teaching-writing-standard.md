# FANDEX 教学写作标准（teaching-writing-standard）

- 版本：v1.0（2026-09-27，依据四篇样板与开放课程方法论研究制定）
- 适用范围：cnt-content/full/ 全部教学文档
- 样板参照：python/090-VariableConstant、javascript/020-JavaScriptOverviewRuntimeEnv、mysql/110-SQLDataOperationQuery、software-testing/010-TestBasicsMethod

## 1. 定位声明

FANDEX 的每篇文档都是一位工程师导师带着学生解决问题，不是百科词条、不是考试讲义、不是 AI 生成文章。最终目标：学生学会后不再依赖 FANDEX。

## 2. 六段课程模板（借鉴 The Odin Project 的结构思想）

适合跟学的知识型文档按以下骨架组织（段落名可微调，顺序不倒）：

1. **前置知识**：链接到真正的前置文档（不是编号相邻的那篇），写明「还没学过也可以，本文会带」的兜底话；
2. **学习目标**：3-5 条「读完你将能够」，必须是可验证的行为（能预测/能修/能写出），禁止复读章节标题；
3. **问题与实验主体**：见第 3 节；
4. **动手环节**：预测题、修改实验、修 Bug 实录；
5. **应用与边界**：真实项目场景、「何时用/何时不用」；
6. **收尾**：与前后章的关系、官方文档链接、自我检查、总结、下一步。

每篇不超过一个主题；发现自己在写第二个主题时，拆篇或链接出去。

## 3. 叙事骨架：动机倒置修正

禁止以定义/历史/分类开场。每个知识点按「问题 → 尝试 → 受挫 → 概念 → 最小代码 → 预期输出 → 修改 → 练习」推进：

- 开头必须是一个学生能共鸣的具体场景（游戏排行榜、记账程序、猜数字），禁止「XXX 是一种……」；
- 理论只在实践受挫后出现，且必须回答「为什么需要它、没有它会怎样」；
- 「历史与演化」一律删除；与旧版本对比压缩到一行，服务迁移理解而非怀旧。

## 4. 零基础真实性测试（每篇必过）

假设读者不知道终端、Git、JSON、API、数据库、编译器。任何首次出现的概念：要么当场一句话解释，要么链接到教它的文档；前向引用（用到了后面才教的东西）必须明示「先混个眼熟，第 N 篇讲透」。违反即断层。

## 5. 语言风格

- 直接、准确、有耐心、有工程感；允许适度幽默、反例、吐槽、真实报错；
- 禁止教科书腔（「本章主要介绍」「综上所述」「顾名思义」「具有以下特点」连用）；
- 禁止鸡汤、营销腔、低幼化、无意义故事；
- 每句都要承载信息：一句话能说清的不写五段；凑字数的内容写完即删。

## 6. 结构红线（写完自查）

1. 无 emoji、无位图；图示用 Mermaid/SVG；
2. 代码块全部标注语言；每个示例给预期输出；
3. frontmatter 只手写 title/description/related/prerequisites/difficulty，托管字段交给 sync；
4. 长文（正文超 10000 字符）必须有「前置知识」或「学习目标」章节；
5. 引用第三方内容注明原始出处与许可（见 technical-verification-standard.md 的许可纪律）；
6. 同模块不出现两篇同主题文档；发现自己要写的内容已有近亲，先去 MERGE（见 document-migration-map.md）。
