# 练习标准（exercise-standard）

## 1. 练习密度要求

- beginner 与 intermediate 文档：至少一组练习（四种题型中至少三种）；正文无练习会触发质量门禁告警；
- advanced 与纯参考文档：至少提供「自检问题」替代动手练习；
- 练习紧跟正文对应小节（借鉴 Full Stack Open 的 1:1 紧邻原则），不集中堆在文末。

## 2. 四种标准题型

1. **预测题**：给代码，先写答案再运行验证。用于训练「读代码脑内执行」；
2. **修改题**：给可运行代码与明确改动目标（改参数、加功能、换数据），观察行为变化；
3. **修 Bug 题**：给带真实 bug 的代码与真实报错，要求按读报错三步定位后修复；
4. **挑战题**：脱离示例的开放任务，不给代码，允许给数据结构要求与验证断言。

## 3. 提示梯度（借鉴 freeCodeCamp 的 user story 验收）

- 练习必须可自查：预测题给预期输出（放折叠提示或倒序位置）；修 Bug 题给报错原文；挑战题给 `assert` 自测断言或验收清单；
- 挑战题提示分两级：「提示」给思路方向，「展开」给关键 API 名；正文不直接给答案代码；
- 每道练习标注预计用时（5 分钟 / 15 分钟 / 半小时），让学生校准节奏。

## 4. 知识复现机制

- 同一概念必须在 ≥3 个上下文重现：本篇练习、后续章节顺带使用、模块出口项目；
- 模块内跨章回指用站内链接（`/模块/文档`），禁止重复讲解（一句带过 + 链接）。

## 5. 禁止事项

- 禁止无断言的「假练习」（跑一下、看看、体会一下）；
- 禁止抄写题（把正文代码抄一遍）；
- 禁止与本章知识无关的谜题（为了有趣而趣味）；
- 禁止答案直接写在题目下方不加分隔（先答后验的结构必须保持）。
