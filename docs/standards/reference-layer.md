# 参考层标准（reference-layer）

- 版本：v1.0（2026-09-27，依据勘察结论中的 29 篇超大文档 SPLIT 待决项制定；架构决策：**设立参考层作为文档定位约定，不改变站点信息架构**）

## 1. 决策与理由

FANDEX 不新增独立的目录树或站点分区；「参考层」是一种**文档内定位约定**：同一模块目录下，教学文与参考书并存，靠定位声明区分。理由：勘察确认的超大文档（Top30 中约一半是「学术模板小书」）内容本身有保留价值，问题只在定位错配——被机器前置、被当作入门教材。拆分是昂贵的二次生产，先正名再逐步拆。

## 2. 参考层判据（满足其一即可标注）

1. 单篇同时覆盖 3 个以上可独立检索的主题（如 Stream 的数据结构/消费者组/集群/监控）；
2. 覆盖运维全链（原理 + 调优 + 监控 + 故障排查）的参考书式文档；
3. 深水区机制推演为主、无动手闭环的专题文。

## 3. 参考层文档的义务

1. 正文首部保留定位声明引用块（脚本统一注入）：「本篇为进阶参考书（参考层），面向已完成本模块主线的读者；入门请先走学习路径前序阶段」；
2. 不作为任何 beginner 文档的前置（迁移映射已核对）；
3. 学习路径中只允许出现在高阶 stage；
4. description 不得使用占位句式；
5. 遵守与其他文档相同的准确性与许可标准——参考层不是降质豁免，只是受众声明。

## 4. SPLIT 判据与节奏

参考层文档若超过 100KB 且主题边界清晰，按主题拆为 2-4 篇（每篇仍属参考层）；拆分随各模块深水区批次执行，不做一次性批量。拆分前先答三问：拆出的每篇能否独立成立？路径节点如何调整？旧 slug 是否需要保留跳转？
