34	### 1.3 设计动机深度分析
35	
36	Daniel Rosenwasser 在 [TypeScript 4.1 Release Notes](https://devblogs.microsoft.com/typescript/announcing-typescript-4-1/) 中阐述了类型体操的三大核心动机：
37	
38	> **动机一：消除运行时开销的类型派生。** 在大型企业级项目中，开发者经常需要从一个基础类型派生多个变种（API 响应类型、表单字段类型、ORM 实体类型）。通过运行时函数派生会增加 bundle 体积与执行开销；类型体操允许在编译期完成所有派生，运行时零成本。
39	
40	> **动机二：表达复杂业务约束。** 例如，约束"用户表单中填写的字段必须是 `User` 类型的可选字段子集"。这类约束在传统类型系统中难以表达，类型体操通过映射类型 + 条件类型 + `infer` 实现了类型层谓词。
41	
42	> **动机三：探索类型系统的表达边界。** TypeScript 团队希望验证类型系统是否足够强大以支持声明式 schema、查询语言类型层解析等高级场景。类型体操社区（type-challenges）的活跃度证明了这一方向的价值。

332	Go 1.14 的异步抢占流程：
333	
334	```text
335	sysmon goroutine (每 10-20ms 检查一次):
336	    for each running G:
337	        if G.schedtick 未变化 && G 运行时间 > 10ms:
338	            tgkill(pid, tid, SIGURG)  // 发送信号
339	
340	信号处理函数 (preemptM):
341	    保存全部寄存器到 g.sigctx
342	    修改 PC = asyncPreempt
343	    返回用户态
344	
345	asyncPreempt:
346	    保存当前 goroutine 上下文到 g.sched
347	    调用 mcall(schedule)
348	    // schedule 会选择新的 G 执行
349	```
350	
351	数学上，异步抢占使得调度延迟上界从 $\infty$（协作式无法抢占 tight loop）降低到约 10-20ms。
